## 一、背景与痛点

| # | 痛点 | 证据 |
| :-- | :--- | :--- |
| P1 | **写文档与跑测试在两个世界**：用户在任意编辑器写 `.md`/`.http`，跑测试要切终端；TUI 的历史快照还原只能反向编辑"已存在的请求"，不能从零编写文档 | `src/tui/handlers/editor.rs` 仅快照还原场景 |

| P3 | **文档质量约束靠自觉**：读者画像头部、可运行示例等写作约定没有任何工具强制，靠 code review 兜底 | 写作约定散落在对话与 README，无模板化承载 |

## 二、定位与边界（先化解与非目标的冲突）

Web UI 技术方案的非目标写明"不做网页版编辑器/发送器"。该红线针对的是 **Postman 式表单构造器**（结构化 UI 组装请求）。本功能的本质不同：

> **编辑对象是文档源文件（文本层），不是请求对象（结构层）。** 用户在浏览器里编辑的就是磁盘上的 `.md`/`.http` 原文——保存即落盘、Git 即协作、CLI/TUI/Web 三端读同一文件。它不是"请求构造器"，是**可执行文档的浏览器视图 + 文本编辑器**，为 Markdown 一等公民（护城河 A3）补上浏览器侧的写路径。

**一句话定义**：活文档工作台 = 在浏览器中完成「读文档 → 改文档 → 跑文档」的闭环，全程以磁盘文件为唯一事实来源。

## 三、用户故事（Stage 0 合规）

- **用户**：Given 我在浏览器打开工作台，When 我编辑某个 `.md` 的一个请求块并保存，Then 磁盘原文件原子更新、Git 可见 diff，且保存前语法校验失败时不落盘并标注问题块。
- **用户**：Given 我选中一行自然语言，When 我触发 AI 断言生成，Then 编辑器内展开为标准 `@assert` 行（执行期零 AI 依赖原则不变）。
- **测试人员**：Given 批量报告中有失败块，When 我从报告页点"编辑"，Then 定位到文档对应块，修改保存后单块重跑验证。
- **开发者**：Given 工作区外路径，When 我请求读写，Then 服务拒绝（路径越界防护）。

## 四、功能定义（需求清单）

| # | 需求 | 优先级 | 验收标准 | 兜底项 |
| :-- | :--- | :-: | :--- | :-: |
| R1 | **工作区浏览**：`rupost web --write` 下 `/docs` 列出 workspace 根内全部 `.md`/`.http`（递归）；路径规范化校验，越界一律拒绝 | P0 | `tests/` E2E：越界路径（`../`、符号链接逃逸）返回 403 | 是 |
| R2 | **编辑与保存**：文本编辑；保存 = 原子写回原文件（temp + rename）；**保存前以 `parse_content()` 校验，语法错误即拒存**并回标问题块——不变量：**磁盘上的文档永远可执行** | P0 | E2E：写坏一个围栏块 → 保存被拒 → 修正后保存成功 → `rupost t 该文件` 通过（三端同源 round-trip） | 否 |
| R3 | **文档结构侧栏**：复用 parser 列出全部请求块（`###` 标题 + method + URL + 行号），点击滚动定位 | P0 | 对 `examples/basic.md` 渲染出的块列表与 CLI 解析结果一致（单测复用同一 parse 断言） | 否 |
| R4 | **就地运行**：单块运行 / 整文件运行，可选 `-e` 环境；结果面板复用 RunEvent SSE 流；失败断言定位回编辑器对应块 | P1 | E2E：修改某块 → 单块跑 → 失败 → 面板高亮该块失败断言 | 是（整文件运行兜底） |
| R5 | **变量提示**：当前环境变量只读展示；`{{var}}` 语法高亮 | P1 | 未定义变量在侧栏可见标注（提示但不阻断） | 是 |
| R6 | **保存冲突保护**：保存时校验文件 mtime/内容哈希，被外部修改则拒绝并提示刷新，**不自动合并** | P1 | E2E：外部改文件后保存 → 409 拒绝 | 否 |
| R7 | **新建与片段**：新建文档走既有 `template` 策略（含读者画像头部行，见 §五）；插入请求块片段，片段以"可运行示例"为单位（带真实 URL 与至少一条 `@assert`），非空壳 | P2 | 新建 SSE 文档模板即 `template sse` 同源产出 | 是 |
| R8 | **AI 编辑辅助**：选区自然语言 → `ai assert` 标准断言行；`# @ai-assert` 注释 → 原地展开（复用 `ai::resolve`）；产物一律是标准文本行 | P2 | 展开结果与 CLI `ai resolve` 输出一致（同一翻译器） | 是 |

**写安全是本功能最大的姿态变化**（Web UI 此前只读）：写能力由 `--write` 显式开启，默认关闭；`--host` 开放远程时 `--token` 必选。路径越界与写入校验为 P0 测试强制项。

## 五、写作约定工具化（引用规则落进功能）

用户侧的 md 写作规则不再靠自觉，由本功能承载：

| 写作规则 | 工具化落点 |
| :--- | :--- |
| 单一事实来源 | 编辑器无影子状态、无私有缓存格式：所见即磁盘文件；报告页链接回文档锚点，文档与报告互为引用 |
| 读者画像先行 | 新建文档模板（R7）头部强制两行：「本文给谁看 / 读完能做什么」——写进 template 策略，而非示例示范 |
| 例子优先于定义 | 片段库（R7）以可运行示例为单位：插入即包含真实请求 + 至少一条 `@assert`，拒绝空壳模板 |
| 文档随代码走 | 保存即 Git diff，网页侧不存在"云端草稿"；改行为的提交自然包含文档更新（文档即代码） |

## 六、非目标

- **不做表单式请求构造器**：一切编辑发生在文本层；结构化 UI 组装请求仍属红线。
- **不做可视化断言构建器**：断言保持文本行形态；AI 只做"自然语言 → 标准行"翻译。
- **不做多人协同**：无锁服务、无合并、无在线状态；冲突策略就是 R6 的拒绝。
- **不做文件管理**：重命名/移动/删除不在 v1 范围（只新建与编辑）。
- **不编辑非文本资产**：二进制、图片、超大文件（阈值见待决问题 4）。

## 七、技术草案（实现细节待 Accepted 后细化为执行计划）

- **前置**：Web UI Phase 1（`src/web/` server + RunEvent SSE）已交付；本功能全部落位 `src/web/` Adapter 内，**零内核改动**——校验用 `parser::parse_content`（`src/parser/mod.rs:20`），模板用 `template::get_templates`，AI 展开用 `ai::resolve`，运行走既有 UseCase。
- **编辑器组件（重开 K3 决策）**：推荐 CodeMirror 6（md + http 语法包，约 200KB gzip）；Monaco 过重；textarea 为兜底。资产体积红线（原方案 1MB）需随之重审。
- **API 草图**：`GET /api/docs`（列表）/ `GET /api/docs?path=`（读）/ `PUT /api/docs?path=`（校验+原子写）/ `POST /api/docs/run`（单块/整文件，SSE 复用）。
- **验证**：round-trip E2E（R2）是本功能的生命线测试；越界 403、冲突 409、模板转义沿用 Phase 0 既有测试。

## 八、评审待决问题

1. **写开关默认态**：`--write` 默认关闭（推荐，姿态最保守）还是 127.0.0.1 默认开、远程默认关？
2. **编辑器组件**：CodeMirror 6（推荐）随 Phase 2 一次性引入，还是先 textarea 后升级？
3. **"磁盘永远可执行"不变量**：语法错误拒存（推荐，保单一事实来源纯度）还是允许保存草稿但标红？
4. **大文件阈值**：建议 1MB 拒编辑（工作台面向文档，非数据文件），是否同意？
5. **批次切分**：R1–R3（P0）与 R4–R8 是否同 PRD 分两批交付？推荐分批：P0 先闭环"改文档"。
