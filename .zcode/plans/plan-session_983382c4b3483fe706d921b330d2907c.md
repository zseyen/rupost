# TUI 流式调试深化：SSE/WS 接入 + 授权 + 消息搜索

## 背景与根因（勘察实证）

1. **授权链路断裂**：TUI 从不加载 rupost.toml/.env/系统环境变量（`src/tui/` 对 `ConfigLoader` 零引用），`state.variables` 是空 `VariableContext::new()`——`Authorization: Bearer {{token}}` 以字面占位符出门，SSE/WS 调试的授权必失败。CLI 的标准做法在 `runner/app.rs:111-124`（`ConfigLoader::find_and_load()` + `build_context(config, env, cli_vars, Some(".env"))`），可直接复用。
2. **WS 只能被动查看**：runner 执行 `@websocket` 剧本结束即 drop 连接（`ws_runner.rs:119` → `session.rs:197-201` Disconnected），TUI 无交互发送。可复用资产：`WsSession::send_frame`（session.rs:104，重连期入 pending 队列）、`get_history`、指数退避重连——TUI 侧独立建会话即可，不必改 runner 执行模型。
3. **消息搜索零实现**：keybindings.md:48-55 早已预留 `/`、n/N、Esc 语义；`InputMode::Filter`（侧栏 `/` 过滤）是完整可克隆的模态模式；三视图（HTTP/SSE/WS）渲染均为"整列表 → scroll 切片 → Paragraph"（`ui/response.rs`），统一高亮挂载点 = 切片后、Paragraph 前。

## 方案设计（四个功能域）

### 域 1：变量上下文接入（授权的地基）
- `app.rs run_async` 启动时对齐 CLI：`ConfigLoader::find_and_load()` + `build_context(&config, env, cli_vars, env_file)` → `state.variables`（现有 captured_vars extend 逻辑不变，叠加其上）。
- CLI 透传：`rupost tui [--env <name>] [--var k=v ...] [--env-file <path>]`（复用 `Commands::Test` 的参数定义模式，main.rs 分发进 `tui::run(initial_file, opts)`）。
- 验证：单测（变量解析）+ 冒烟。

### 域 2：快速授权 UI
- 全局 `A` 键 → `InputMode::Auth(Box<TextArea>)` 弹窗（克隆 Filter 模式）→ Enter 存 `state.variables` 的 `__quick_auth` 键；`trigger_request_execution` 在变量解析后、发送前，若请求无显式 `Authorization` header 则注入 `Authorization: <值>`（显式声明优先）。
- 状态可见：底栏/编辑器标题显示 `AUTH set`；Esc 取消。变量同样可用 `{{__quick_auth}}` 引用。

### 域 3：SSE/WS/HTTP 消息搜索
- `InputMode::Search(Box<TextArea>)`：**Response 面板焦点**下 `/` 进入（与侧栏 Filter 不冲突）；实时匹配。
- 高亮：`ui/response.rs` 三分支"切片之后、Paragraph 之前"统一一个 `highlight_matches(sliced, query)` 函数（大小写不敏感子串 → 命中 Span 加强调色），一处覆盖三视图。
- 跳转：Search 态与退出后均可 `n/N`（query 留存 `state.search_query`）——在当前视图的视觉行列表中按 `response_scroll` 向下/上找下一个匹配视觉行并回写 scroll；流式自动吸底逻辑（scroll=9999）在搜索态暂停。
- 顺带修正既有 bug：`handlers/response.rs:28` 的 `response_total_lines`（WS 帧 > SSE 行 > HTTP 视觉行的计数与 wrap 后视觉行不一致）改为与各分支视觉行一致——搜索跳转依赖正确总行数。
- 文档：keybindings.md 的预留语义就此兑现，帮助弹窗（ui/mod.rs help_text）加条目。

### 域 4：WS 交互式发送（最大块）
- **TUI 侧独立会话，不改 runner**：对 `@websocket` 请求（编辑器内容解析出的 ParsedRequest），新键 `W`（Editor 焦点）→ TUI 直接构造 `WsConfig`（url/headers 从解析后请求取，`ws_runner.rs:102-114` 同款；Authorization 含快速授权注入）→ spawn `WsSession`（session.rs 现有 actor）→ 后台 task 把 session 帧转发为 `TuiEvent::WsFrame`（**复用现有 WS 渲染/环形/滑窗全链路**）。
- 发送：会话活跃时 `S` 键 → `InputMode::WsSend(textarea)` → Enter 调 `WsSession::send_frame`（错误浮 `last_error` 状态栏）→ 帧实时回显（is_send=true 路径已有）。
- 生命周期：`state.ws_session: Option<WsSessionHandle>`；关闭用 `Esc`（会话焦点时）或 `D` 键（drop session → 连接关闭）；与 runner 剧本执行互斥（`is_loading` 或会话活跃时 r/R/W 互拒，状态栏提示）；断线自动重连沿用 session 现有逻辑。
- 测试：TcpListener WS mock server 集成测试（websocket_integration_test.rs 有先例）——交互会话建立/发送/收帧回显/关闭；授权 header 进握手的断言。

## 非目标（PRD 显式裁剪）

- SSE 事件结构化保存（id/event/data 分离建 per-event 模型）——搜索按文本行已覆盖，YAGNI
- 多 WS 会话并行、重连策略定制、SSE 交互发送（SSE 本为单向推送）
- runner 内部 `@websocket` 剧本执行模型的改动（交互会话走 TUI 独立路径，零侵入）

## 风险与裁决

- **WS 会话与 TUI 单线程渲染**：session actor 自带 tokio task，TUI 主循环仅经 event 通道消费——与现有 stream 转发同构，无新增锁。
- **交互会话期间的帧洪泛**：100 帧环形 + 溢出重建已有；滑窗读日志兜底完成态。
- **工程量**：约 3-4 天当量，域 4 占一半；每域独立可交付、可砍。
