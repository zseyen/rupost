## 一、环境维度：需求与安全画像

> **安全语义绑定声明而非名字**（审查修正）：prod 判定挂环境档的显式 `safety = "production"` 字段，不挂字符串名（production/prd/live、prod-cn/prod-eu 多区域均可声明多档共享同一底线）。X2–X6 全部挂声明。

### 1.1 开发环境（dev）——快迭代主场

| 维度 | 内容 |
| :--- | :--- |
| **特征** | 单机本机；调试数据多为假数据；变更频率天级 |
| **需求重点** | R1 单请求重跑（修复回路）、R2/R4 失败初诊与就地归因、diagnose、TUI、Mock 同源（A5）、`--templatize-host`、`ai assert`/`--last`、generate 沉淀 |
| **安全底线** | 凭据不入版本库（`.env` gitignored；`dc1f048c` 泄密修复先例）；redaction 可关闭 |
| **体验目标** | "改一处 → 验一处 → 沉淀"分钟级闭环 |

### 1.2 测试环境（test）——两个不同安全级别的子档（审查修正：不再混写）

| 子档 | 特征 | 差异化要求 |
| :--- | :--- | :--- |
| **CI 靶场** | 短生命周期；持有**部署密钥**（比 dev 更敏感）；日志全团队可见且长期留存 | redaction 默认开的理由是**留存面**；R5 triage / T8 junit 的主消费场景 |
| **QA 共享集群** | 长生命周期；多人并发 | **状态污染是主痛点**——`--env` 隔离（X4）的真实动机；快照分享脱敏（`--mask`/`--encrypt`，backlog） |

### 1.3 生产环境（prod，safety=production 档）——只读取证与强合规

| 维度 | 内容 |
| :--- | :--- |
| **特征** | 真实 PII；开发者通常无集群权限；行为须可审计；两类场景：发布验证（replay 灰度比对——**灰度是 prod 内的部署策略而非第四环境**，即双 host 比对）与线上请求级取证 |
| **需求最小集** | ①R7 钩子（**仅以默认关形态存在**，显式开启才生效）；②replay 比对（Smart Diff + 时延退化）；③**审计留痕**：每次 prod 查询/取证写入结构化 run log（谁/何时/查了什么/命中几行）——**脱敏后落盘**（与 X2 联动，审计记录本身不得含凭据），day-one 结构化（可集中化，避免商业阶梯二返工） |
| **安全底线** | ①凭据零落盘强制（见 X3）；②redaction 只升不降（X2，`max(配置, safety 底线)`）；③查询最小化（trace-id 精确检索 + 行数上限）；④危险操作护栏（X5，告警+显式确认）；⑤**AI 出站默认关闭**（X6：safety=production 下响应体不得默认外发 LLM API，与 R7 同一开关族——"管住进来"也要"管住出去"） |
| **全部底线可显式 override**（审查补强） | 企业试用摩擦兜底——每条护栏有显式逃生口并留痕，避免"保护变成墙" |
| **显式边界** | 平台日志 adapter / kubectl 内建聚合 = Won't do（future_backlog 7–9） |
