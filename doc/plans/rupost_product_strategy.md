## 1. 产品核心定位与差异化价值

在竞争激烈的 API 工具市场中，RuPost 的定位是 **“AI 增强的文学化 API 测试平台 (AI-Enhanced Literate API Testing)”**。

与主流竞品的本质差异：
*   **vs Postman/Apidog (重型 GUI)**：RuPost 拒绝臃肿，采用高性能 Rust 构建，提供极速的 CLI/TUI 体验。
*   **vs Hurl (硬核脚本)**：Hurl 强制用户学习自定义 DSL；RuPost 将 **Markdown 视为一等公民**，让开发者在编写日常 `README.md` 的同时完成测试用例。
*   **vs Keploy (黑盒录制)**：录制生成的用例往往难以阅读；RuPost 提倡 **“意图驱动”**，通过 `@ai_assert` 让测试用例保持自然语言般的易读性。
*   **vs Slumber (TUI 管理器)**：Slumber 需要维护复杂的 YAML 集合；RuPost 奉行“文档即集合”，零额外配置。

**三大核心破局点**：
1.  **文档即代码的终极形态**：消除文档与测试的裂痕。
2.  **AI 原生驱动**：让测试编写从“写代码”变为“提需求”。
3.  **极简主义美学**：HSL 动态配色与平滑微动画，打造沉浸式终端体验。

## 2. 商业化变现路径 (Open Core 策略)

采用自下而上 (Bottom-up) 的策略，用开源工具吸引开发者，通过增值服务向团队和企业收费。

### 阶梯一：AI 生产力订阅 (AI-as-a-Service)
*   **核心功能**: 无限次 `@ai_assert` 生成、`@ai_fix` 自动修复测试、一键 OpenAPI 转可执行 Markdown。
*   **付费模式**: 个人 Pro 版（月度订阅）或 Token 计费。

### 阶梯二：团队安全与协作 (SaaS)
*   **核心功能**: 敏感环境变量的云端加密同步、团队共享的历史请求看板、与 GitHub Actions 的深度集成。
*   **付费模式**: 按团队席位计费 (Per Seat/Month)。

### 阶梯三：企业级高性能基础设施 (Infra-as-a-Service)
*   **核心功能**: 基于 Rust 协程的云端万级并发压测 (`@bench`)、全球分布式的极速 Mock 网关。
*   **付费模式**: 按量计费或企业年费私有化部署。

## 3. 多角色场景落地与协同价值

RuPost 通过一个统一的 Markdown 协议，打破了研发链路中的“角色孤岛”。

1.  **开发者 (Developer)**
    *   **痛点解决**: 消除“写代码、写文档、写测试”的三重重复劳动。
    *   **价值**: 同事间 `git pull` 即可同步测试环境；输出即标准文档。
2.  **测试人员 (QA/Tester)**
    *   **痛点解决**: 彻底终结“无法复现”的拉扯。
    *   **价值**: 将“口头描述 Bug”升级为“发送一个包含完整上下文失败的 `.http` 脚本”。
3.  **现场调试工程师 (Field Debugger)**
    *   **痛点解决**: 现场排查效率低，信息收集不全。
    *   **价值**: 利用 TUI 交互式翻阅请求历史，一键录制现场报错流量并生成诊断快照包寄回研发中心。
4.  **终端用户 (End User)**
    *   **痛点解决**: API 文档经常过期且不安全。
    *   **价值**: 用户消费的静态文档是由 RuPost 引擎真实运行生成的，保证绝对准确，同时底层执行引擎对用户安全隔离。

## 4. 总体开发路线图 (Implementation Plan)

为实现上述愿景，开发工作按垂直切片分为四个阶段：

### Phase 1: 内核与文档增强 (Foundation)
*   **重点**: 夯实基础，确立“文档即测试”的体验。
*   **Task**: 增强 Markdown 解析器，实现跨代码块的变量共享与上下文传递；深化 `@capture` 和基础变量函数。

### Phase 2: 极致 TUI 交互体验 (Immersive UI)
*   **重点**: 打造终端工具的美学壁垒。
*   **Task**: 开发 `rupost h i` 交互式历史仪表盘；实现终端内的“Time-Travel”参数修改与调试重发。

### Phase 3: AI 意图层集成 (Intelligence)
*   **重点**: 引入 LLM 降维打击传统测试编写。
*   **Task**: 跑通 `@ai_assert` 的原型逻辑，将自然语言转化为内部断言；研发 `@ai_fix` 提供交互式错误修复建议。

### Phase 4: 商业化基础设施 (Business Expansion)
*   **重点**: 构建可直接变现的性能服务。
*   **Task**: 实现高性能并发压测模块 (`@bench`) 及终端波形图渲染；开发 Doc-Mock 引擎，一键从文档启动真实 Mock 服务。
