# RuPost AI 开发使用旅程设计（Developer Journey First）

> **创建日期**: 2026-10-27
> **性质**: 设计原则文档——**旅程先于功能**。功能是旅程断点的解，凡不能映射到旅程阶段的 AI 功能一律砍掉（YAGNI 的旅程化表述）
> **上游输入**: [竞争格局复审](file:///Users/zsyzzx/project/rust/rupost/doc/competition/2026-10-25-competitive-landscape-review.md)（A/B/C 层）、[AI 迭代 PRD](file:///Users/zsyzzx/project/rust/rupost/doc/plans/2026-10-27-ai-context-assert-and-zero-config-prd.md)、[bootstrap 提案](file:///Users/zsyzzx/project/rust/rupost/doc/plans/2026-10-26-ai-bootstrap-proposal.md)
> **主轴画像**: 后端开发者"一个需求周期"（对接新服务 → 调试 → 沉淀 → 回归 → 演进），辅以评估者入口

---

## 1. 设计原则

1. **旅程先于功能**：不从"AI 能做什么"出发，从"开发者在时间轴上卡在哪里"出发。每个功能必须回答"它消除旅程的哪个断点"，答不上来的砍。
2. **断点即优先级**：开发者流失/价值流失最严重的断点 = 最高优先级。
3. **运行期是 AI 禁区**：旅程中"回归执行"阶段（S5）保持确定性离线，这是结构承诺不是功能取舍。
4. **文档先行为主轴**：API 先行只作为 S1 冷启动入口（见 §3 漏斗模型）。

## 2. 旅程八阶段与断点分析

| 阶段 | 开发者在做什么 | 频率 | 现有能力 | 断点（未解的摩擦） | AI 动词 |
| :-- | :--- | :--- | :--- | :--- | :--- |
| **S0 发现评估** | 装上 → 5 分钟判断是否值得引入 | 一次性 | 单二进制、examples、run_all.sh | 分发（cargo install/homebrew，复审 C 层已登记）；零配置 AI 体验门槛 | —（第一印象必须是确定性） |
| **S1 冷启动** | 存量 API/Postman/OpenAPI/curl 资产 → 变成 rupost 活文档 | 一次性（按服务） | `.http` 兼容（事实标准入场券） | **导入器缺位**：存量用户迁移靠手抄 | 生（gen） |
| **S2 契约设计** | 前后端并行：先写 `.md` 契约 → mock 起仿真 → 后端照契约实现 | 每个新接口 | ✅ A5 Mock 同源 + 条件变体（完整兑现） | 无——这是卖点阶段，保持 | — |
| **S3 日常调试** | CLI 内联 / TUI / 流式调试 / Cookie 管理 | 天级高频 | ✅ 全部核心能力（A1/A2） | 无硬断点；软性糖霜：失败归因解释 | 诊（低优） |
| **S4 资产化** ★ | 调试结束 → 成果沉淀为回归资产 | 周级，**价值跃迁点** | history（含全量 body）、`generate`（机械还原）、快照 | **最大断点：调试成果转瞬即逝**——机械还原无断言/无语义，离"可回归"差一步 | 炼（最高优）+ 翻 |
| **S5 回归 CI** | `rupost t` 进 CI，DAG 批量，失败拦截 | 每次提交 | ✅ A4 DAG/拓扑/并行/快照重放、JSON 报告 | junit 报告（CI 生态接入件，复审已登记） | —（**运行期零 AI**） |
| **S6 失败诊断** | CI 红 → 定位 → 修复 → 回 S3/S4 | 事件驱动 | debug 模式、diagnose | 归因靠人肉读响应 | 诊（中优，优先做 LLM 流式响应变体） |
| **S7 协作演进** | git pull 同步测试；PR review `.md`；契约 V1→V2 演进 | 月级 | ✅ Markdown 活文档（A3）、Git 原生 | 无——叙事保持 | — |

### 断点解读

- **S4 是整个旅程的价值跃迁点**：S3 的调试输出（终端转瞬即逝）与 S5 的回归输入（确定性资产）之间隔着一条沟——`generate` 的机械还原能跨过去一半（有请求、无语义），`ai bootstrap` 补上另一半（断言/`@capture`/`@depends-on` 语义增强）。这条沟不填，rupost 停留在"调试工具"；填上，升维为"回归引擎"（A4 对位 newman/k6 生态位）。
- **S1 是入口宽度问题**：rupost 对 greenfield 极友好，对 brownfield（存量 API 占绝大多数）需要一条迁移坡道。
- **S0 的零配置**已在 [AI 迭代 PRD](file:///Users/zsyzzx/project/rust/rupost/doc/plans/2026-10-27-ai-context-assert-and-zero-config-prd.md) 立项，此处不重复。

## 3. AI 动词在旅程中的落位（采纳漏斗）

```
S0 评估 ──→ S1 冷启动 ──→ S2/S3 日常 ──→ S4 资产化 ──→ S5 回归 ──→ S6 诊断闭环
  │            │                        │              
  │            生（gen）：                 炼（bootstrap）：              
  │            OpenAPI/Postman/NL         history/快照 → 语义增强资产     
  │            → .md 初稿（一次性）        翻（assert）：断言降门槛          
  │                                                                      
  └─ 零配置（PRD 已立项）保证评估者能走到 S1                              
                                     全部汇入：文档 = 唯一事实源 → Git → CI
```

- **生 = 入口**（API 先行当门票）：只做冷启动初稿，落盘为 `.md` 后 AI 退场，文档接管事实源。
- **炼 = 燃料**（文档先行的飞轮）：唯一强化 A3/A4/A5 护城河的动词，竞争力度最高。
- **翻 = 转化**：S4 资产化时降低断言书写门槛。
- **诊 = 留存**：S3/S6 的体验糖霜，优先做"LLM 流式响应诊断"变体以借力 A1 空白。
- **S2/S5/S7 无 AI**：契约设计、回归执行、协作演进是确定性叙事的本体，AI 进入反而稀释定位。

## 4. 由旅程推导的功能优先级

| 优先级 | 功能 | 服务的旅程断点 | 状态 |
| :-- | :--- | :--- | :--- |
| P0 | 零配置接入链（env > 用户级配置 > Ollama 探测） | S0 评估流失 | PRD 已立项 |
| P0 | `--last` 上下文断言 + 脱敏 | S4 资产化门槛 | PRD 已立项 |
| P1 | **`ai bootstrap --from history`** | **S4 最大断点** | 提案已立项，下一主线 |
| P2 | **OpenAPI 导入 + AI 生成 mock/断言**（`ai gen`；Postman 导入登记后续） | S1 冷启动坡道 | **已立项**（2026-10-27，[开发计划](file:///Users/zsyzzx/project/rust/rupost/.workspace/rupost-ai/doc/plans/2026-10-27-ai-openapi-gen-plan.md)） |
| P3 | `ai explain`（先做 LLM 流式变体） | S3/S6 留存糖霜 | 候选 |
| 登记 | junit 报告、cargo install/homebrew 分发 | S0/S5 工程事务 | 非功能，发版前 |

## 5. 反模式清单（旅程不服务则砍）

| 反模式 | 被砍理由 |
| :--- | :--- |
| AI 聊天面板 / 通用对话入口 | 不服务任何阶段；rupost 是工具不是助手 |
| 运行期 AI（自动修复、失败重试判优、`@ai_assert` 执行） | 破坏 S5 确定性与离线隔离（已裁决 Won't do） |
| 从代码持续生成文档（code-first 文档流水线） | 产物是只读快照，必然漂移——与"文档即事实源"主轴冲突 |
| AI 评分/置信度体系 | YAGNI（bootstrap 提案已裁剪）；warnings + 人工 review 覆盖 |
| 历史云端同步、AI 云端资产库 | 本地文件即事实源（Bruno 已占的叙事不跟） |

## 6. 结论

开发使用旅程的主轴是一条**价值升维链**：`评估 → 冷启动 → 调试 → 资产化 → 回归引擎`。AI 四个动词各自卡位一个转化环节（生=入口、翻=门槛、炼=跃迁、诊=留存），其中 **S4 资产化是最大断点也是最大机会**——这正是 bootstrap Phase 1 被列为下一主线的原因。功能设计的检验标准从此统一为一句问话：**"它消除旅程的哪个断点？"**
