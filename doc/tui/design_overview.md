# RuPost TUI 界面设计方案

> **设计目标**：打造现代化、极简、高效的终端 API 测试界面，让开发者在终端中也能享受媲美 GUI 工具的丝滑体验。

---

## 🎯 设计原则

1. **快速上手**：首次使用即可directly开始工作，无需查阅文档
2. **键盘优先**：所有操作均可通过键盘完成，支持 Vim/Emacs 风格导航
3. **视觉引导**：清晰的帮助提示、快捷键显示、状态反馈
4. **高效工作流**：最少按键完成常见任务
5. **美观现代**：使用现代终端特性（256 色、Unicode 图标、平滑过渡）

---

## 方案一：经典三栏布局（Postman-like）

### 📐 布局设计

```
┌─────────────────────────────────────────────────────────────────┐
│ RuPost TUI v1.0                    [dev]  ⚡ Ready   [?] Help  │
├─────────────┬───────────────────────────────┬───────────────────┤
│             │                               │                   │
│  📁 Files   │  📝 Request Editor            │  📊 Response      │
│             │                               │                   │
│  ▼ examples │  GET {{base_url}}/users/1    │  Status: 200 OK   │
│    basic.ht │  ────────────────────────────│  Time: 145ms      │
│  ▼ tests    │  Headers:                     │  Size: 1.2KB      │
│    auth.md  │  Authorization: Bearer {{tok}}│                   │
│    user.ht  │                               │  Headers ▼        │
│  ▶ history  │  Body:                        │  Content-Type:    │
│             │  (empty)                      │    application/j  │
│  [+] New    │                               │                   │
│             │  Assertions:                  │  Body ▼           │
│             │  @assert status == 200        │  {                │
│             │  @assert body.id > 0          │    "id": 1,       │
│             │                               │    "name": "Ali"  │
│             │  [ Send Request ]  Ctrl+Enter │  }                │
│             │                               │                   │
├─────────────┴───────────────────────────────┴───────────────────┤
│ Tab 切换面板 | Enter 执行 | / 搜索 | Ctrl+T 新建 | q 退出      │
└─────────────────────────────────────────────────────────────────┘
```

### ✨ 核心特性

**左侧：文件浏览器（25% 宽度）**
- 树状结构展示项目文件
- 支持展开/折叠文件夹
- 高亮显示当前选中文件
- 集成历史记录访问
- 快捷键：`j/k` 上下移动，`h/l` 折叠/展开，`Enter` 打开文件

**中间：请求编辑器（40% 宽度）**
- 语法高亮的 HTTP 请求编辑
- 变量预览（hover 显示实际值）
- 实时断言验证提示
- 智能补全（变量、Headers、方法）
- 快捷键：`i` 进入编辑模式，`Esc` 退出，`Ctrl+Enter` 发送

**右侧：响应查看器（35% 宽度）**
- 分标签页展示 Headers、Body、Assertions、Timeline
- JSON/XML 自动格式化与语法高亮
- 支持折叠/展开 JSON 节点
- 断言结果高亮显示（✓/✗）
- 快捷键：`Tab` 切换标签页，`/` 搜索内容

### 🎨 颜色方案

- **主题色**：HSL(210, 100%, 60%) - 现代蓝
- **成功**：HSL(130, 70%, 50%) - 清新绿
- **错误**：HSL(0, 80%, 60%) - 警示红
- **背景**：HSL(218, 20%, 15%) - 深空灰
- **文本**：HSL(210, 20%, 90%) - 柔和白

### ⚡ 优势

- **直观熟悉**：与 Postman/Insomnia 等 GUI 工具布局相似，学习成本低
- **信息密度高**：一屏可见文件、请求、响应，减少切换
- **适合宽屏**：充分利用现代终端的宽度

### ⚠️ 劣势

- **小屏幕不友好**：窄终端（<120 列）体验欠佳
- **固定布局**：灵活性较差，不能根据任务调整

## 方案二：模态化工作流（K9s-like）

### 📐 布局设计

```
┌─────────────────────────────────────────────────────────────────┐
│ RuPost - Request List                         [?] Help  q Quit │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   📂 examples/basic.http                                        │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │ ● GET /users/1                              ✓ 200 145ms │  │
│   │   POST /login                               ✓ 200 89ms  │  │
│   │   DELETE /users/2                           ✗ 404 56ms  │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   📂 tests/auth.md                                              │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │   POST /api/login                           — Not Run   │  │
│   │   GET /api/profile                          — Not Run   │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   📜 History (10 items)                                         │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │   GET httpbin.org/get                       ✓ 200 234ms │  │
│   │   POST api.example.com/data                 ✗ 500 1.2s  │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│ Enter 查看详情 | Space 运行 | e 编辑 | d 删除 | r 刷新 | / 搜索│
└─────────────────────────────────────────────────────────────────┘
```

**按 `Enter` 进入请求详情模式：**

```
┌─────────────────────────────────────────────────────────────────┐
│ GET /users/1                                      Esc 返回列表 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  🔹 Request                                                     │
│  ────────────────────────────────────────────────────────────   │
│  GET https://api.example.com/users/1                            │
│                                                                 │
│  Headers:                                                       │
│    Authorization: Bearer eyJhbG...                              │
│    Accept: application/json                                     │
│                                                                 │
│  ────────────────────────────────────────────────────────────   │
│  🔹 Response                                    ✓ 200 OK 145ms │
│  ────────────────────────────────────────────────────────────   │
│  {                                                              │
│    "id": 1,                                                     │
│    "name": "Alice",                                             │
│    "email": "alice@example.com"                                 │
│  }                                                              │
│                                                                 │
│  ────────────────────────────────────────────────────────────   │
│  🔹 Assertions                                         2/2 ✓   │
│  ────────────────────────────────────────────────────────────   │
│  ✓ status == 200                                                │
│  ✓ body.id > 0                                                  │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│ Space 重新运行 | e 编辑 | c 复制 curl | s 保存到文件           │
└─────────────────────────────────────────────────────────────────┘
```

### ✨ 核心特性

**列表模式（默认）**
- 聚合显示所有可执行的 HTTP 请求
- 分组展示（按文件、按状态）
- 一键运行单个或批量请求
- 实时状态更新（运行中/成功/失败）
- 快捷键：`j/k` 导航，`Space` 运行，`Enter` 查看详情

**详情模式**
- 全屏展示请求与响应
- 分区域显示：Request → Response → Assertions
- 支持滚动查看长内容
- 快捷操作：编辑、复制、保存
- 快捷键：`Esc` 返回，`e` 编辑，`r` 重新运行

**编辑模式**
- 进入 Vim-like 编辑器
- 语法高亮与自动补全
- 保存后自动返回详情模式
- 快捷键：`Ctrl+S` 保存，`Esc Esc` 放弃

### 🎨 颜色方案

- **主色调**：极简黑白灰
- **强调色**：金色高亮（HSL(45, 100%, 60%)）
- **状态色**：绿色（成功）、红色（失败）、黄色（运行中）

### ⚡ 优势

- **专注工作流**：每次只展示一个任务，避免信息过载
- **适应性强**：在任何尺寸的终端都有良好体验
- **键盘高效**：模态化设计，操作逻辑清晰
- **快速切换**：通过快捷键在列表、详情、编辑间流畅切换

### ⚠️ 劣势

- **多步操作**：查看请求需要进入详情模式，比三栏布局多一步
- **上下文切换**：频繁在不同模式间切换可能影响连贯性

## 方案三：混合自适应布局（tmux-like）

### 📐 布局设计

**默认布局（宽屏 ≥120 列）：**

```
┌─────────────────────────────────────────────────────────────────┐
│ RuPost                   [dev]                     [?] q h e s │
├──────────────────────┬──────────────────────────────────────────┤
│                      │                                          │
│  📝 Request          │  📊 Response                             │
│                      │                                          │
│  GET /users/1        │  ┌─ Status ─────────────────┐            │
│  ─────────────────   │  │ 200 OK        145ms      │            │
│  Headers:            │  └──────────────────────────┘            │
│  Auth: Bearer {{tok}}│                                          │
│                      │  ┌─ Headers ────────────────┐            │
│  Body:               │  │ Content-Type: app/json   │            │
│  (empty)             │  │ Content-Length: 1234     │            │
│                      │  └──────────────────────────┘            │
│  Assertions:         │                                          │
│  @assert stat == 200 │  ┌─ Body ───────────────────┐            │
│                      │  │ {                        │            │
│ [ Send ] Ctrl+Enter  │  │   "id": 1,               │            │
│                      │  │   "name": "Alice"        │            │
├──────────────────────┤  │ }                        │            │
│  📂 Files & History  │  └──────────────────────────┘            │
│                      │                                          │
│  ▼ Files             │  ┌─ Assertions ─────────────┐            │
│    basic.http    ●  │  │ ✓ status == 200          │            │
│    auth.md           │  │ ✓ body.id > 0            │            │
│  ▶ History (10)      │  └──────────────────────────┘            │
│                      │                                          │
├──────────────────────┴──────────────────────────────────────────┤
│ Ctrl+F 文件 | Ctrl+H 历史 | Ctrl+E 编辑 | Ctrl+R 运行 | / 搜索 │
└─────────────────────────────────────────────────────────────────┘
```

**窄屏布局（<120 列）：**

```
┌─────────────────────────────────────────────┐
│ RuPost [dev]              [?] q h e s      │
├─────────────────────────────────────────────┤
│                                             │
│  📝 Request                                 │
│  GET /users/1                   [编辑模式]  │
│  ───────────────────────────────────────    │
│  Headers:                                   │
│  Authorization: Bearer {{token}}            │
│                                             │
│  [ Send Request ]  Ctrl+Enter               │
│                                             │
│  ═══════════════════════════════════════    │
│                                             │
│  📊 Response                   ✓ 200 145ms │
│  ───────────────────────────────────────    │
│  {                                          │
│    "id": 1,                                 │
│    "name": "Alice"                          │
│  }                                          │
│                                             │
│  Assertions: 2/2 ✓                          │
│                                             │
├─────────────────────────────────────────────┤
│ Ctrl+T 切换视图 | Ctrl+F 文件 | / 搜索     │
└─────────────────────────────────────────────┘
```

### ✨ 核心特性

**智能自适应**
- 根据终端尺寸自动调整布局
- 宽屏：三栏布局（请求 + 响应 + 文件）
- 窄屏：上下堆叠（请求在上，响应在下）
- 超窄屏（<80 列）：单列模式，通过 Tab 切换视图

**可定制面板**
- 用户可自定义面板大小（类似 tmux 的 resize-pane）
- 可隐藏/显示任意面板
- 保存布局配置到 `~/.rupost/layout.toml`

**多工作区**
- 支持同时打开多个请求（Tab 标签页）
- 快捷切换：`Ctrl+Tab` / `Ctrl+Shift+Tab`
- 标签页显示请求名称和状态

**智能折叠**
- 响应区域自动折叠长 JSON（超过 20 行）
- Headers 默认折叠，点击展开
- 大文件（>10KB）自动分页

### 🎨 颜色方案（支持主题切换）

**Dark 主题（默认）**
- 背景：HSL(220, 15%, 12%)
- 前景：HSL(210, 15%, 85%)
- 强调：HSL(200, 90%, 55%)

**Light 主题**
- 背景：HSL(0, 0%, 98%)
- 前景：HSL(220, 10%, 20%)
- 强调：HSL(210, 100%, 45%)

### ⚡ 优势

- **最佳平衡**：结合了三栏布局的信息密度和模态布局的灵活性
- **普适性强**：任何终端尺寸都有最佳体验
- **高度可定制**：用户可根据习惯调整布局
- **工作区管理**：支持多任务并行，适合复杂场景

### ⚠️ 劣势

- **开发复杂度高**：需要实现自适应逻辑和布局引擎
- **配置学习成本**：高级功能（如自定义布局）需要学习

## 🛠️ 技术选型建议

### Rust TUI 框架

#### 推荐：[Ratatui](https://github.com/ratatui-org/ratatui)
- ✅ **成熟稳定**：tui-rs 的继任者，社区活跃
- ✅ **功能完整**：支持布局、组件、样式、事件处理
- ✅ **性能优异**：增量渲染，低延迟
- ✅ **生态丰富**：有大量示例和组件库

```toml
[dependencies]
ratatui = "0.26"
crossterm = "0.27"  # 跨平台终端库
```

#### 备选：[Cursive](https://github.com/gyscos/cursive)
- ✅ **高层抽象**：更接近传统 GUI 开发模式
- ✅ **内置组件多**：表单、对话框、菜单等开箱即用
- ⚠️ **性能较低**：回调机制开销较大

### 架构设计

```
src/tui/
├── app.rs           # 应用状态管理
├── ui/              # UI 层
│   ├── layout.rs    # 布局引擎
│   ├── components/  # 可复用组件
│   │   ├── request_editor.rs
│   │   ├── response_viewer.rs
│   │   ├── file_tree.rs
│   │   └── status_bar.rs
│   └── theme.rs     # 主题系统
├── event.rs         # 事件处理
├── input.rs         # 输入映射（按键绑定）
└── state.rs         # 状态机
```

**关键设计模式**：
1. **Elm Architecture**：单向数据流，State → View → Event → State
2. **Component Pattern**：每个 UI 组件独立管理自己的状态
3. **Plugin System**：通过 trait 扩展新功能

## 🚀 推荐方案

**综合考虑 RuPost 的定位（极简、美感、高效）和目标用户（终端熟练开发者），我推荐：**

### 🏆 方案三（混合自适应布局） + 方案二的模态化元素

**理由**：
1. **极致体验**：宽屏用户享受高信息密度，窄屏用户也有流畅体验
2. **符合审美**：自适应布局体现"第一性原理"——根据实际情况选择最优解
3. **未来可扩展**：为 WebSocket 监控、GraphQL 等复杂功能预留空间
4. **学习曲线友好**：默认布局简洁，高级功能可按需学习

**实施路线**：
1. **MVP（v0.1）**：实现基础三栏布局 + 文件浏览 + 请求发送 + 响应展示
2. **v0.2**：加入自适应逻辑 + 窄屏优化
3. **v0.3**：引入模态化详情视图 + 多工作区
4. **v1.0**：主题系统 + 自定义布局 + 完整快捷键
